# Terms v2.2 and Privacy Notice v1.3: passwords

For the team's legal person. Written on 25 November 2026 from the code on
the branch that adds passwords.

## Why

Until now GigoMe had no passwords: every login was a 6-digit code sent by
email. From this change, the code is needed once, at sign-up; then people
choose a password and log in with their email and password. They can
still log in with a new code at any time ("Email me a code instead"), and
"Forgot your password?" is a code login followed by choosing a new
password (no reset links). Accounts from before this change have no
password and are asked to choose one after their next code login; they
can skip it.

Supabase (our authentication provider, already named in the Privacy
Notice) stores each password only as a bcrypt hash. GigoMe's own tables
never hold it, and the site can only ask the database whether an account
has a password (`my_has_password()`), never read it.

Terms 4.2 and the Privacy Notice said there are no passwords, so both
change. The owner asked for **fresh acceptance**: everyone, existing
accounts included, accepts Terms v2.2 once on their next visit
(`TERMS_VERSION` and `TERMS_MIN_VERSION` are both `2.2`). Both texts are
dated 25 November 2026; please confirm or give the date they should carry.

The changes are deliberately minimal: only the sentences that became
untrue, plus the matching duty to keep a password safe.
